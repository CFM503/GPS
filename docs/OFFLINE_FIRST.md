# 道路路产智能巡查系统 - 离线优先 (Offline-First) 架构指南

## 1. 核心设计原则

道路巡查现场环境通常处于高山、隧道、省界偏远公路、高速互通或恶劣天气，**现场网络绝不可靠，绝不能假定随时具备 4G/5G 网络**。

系统严格贯彻 **Offline-First（离线优先）** 核心原则：
1. **全功能离线可用**：在完全无网络或飞行模式下，巡线员可正常开启巡查、采集 GPS 轨迹、切片录制行车视频、一键秒级标记路产、补充照片与备注。
2. **本地存储优先落盘**：所有新产生的数据必须首先写入车载设备的生产级本地存储（IndexedDB），确保断电、误触退出或系统崩溃时 100% 数据不丢失。
3. **断网透明化**：网络断开不会弹出阻断性报错，界面右上角清晰呈现网络状态（在线/离线）与待同步队列计数。
4. **网络恢复静默自动同步**：一旦监听至网络恢复（`online` 事件），后台静默启动优先级同步引擎，逐级完成数据上传与状态对齐。

---

## 2. 本地存储架构：IndexedDB 引擎

生产级移动端严禁将轨迹点、大批路产或二进制视频放入 `localStorage`（受 5MB 容量上限限制且同步读写易阻塞渲染主线程造成行车界面卡顿）。

本项目采用生产级 **IndexedDB (`idbStorage.ts`)**，规划了 8 大核心对象仓库（Object Store）：

| 仓库名称 (Store) | 存储内容 | 索引与特性 |
| :--- | :--- | :--- |
| `patrol_sessions` | 巡查会话摘要 | 主键 `id` (客户端业务编号)，记录总里程、状态、时长 |
| `gps_tracks` | 实时 GPS 轨迹点 | 主键自增，复合索引 `session_id`, `point_time`，支持海量轨迹高速分段读取 |
| `assets` | 路产与病害记录 | 主键 `id` (客户端 UUID)，索引 `patrol_session_id`, `type_id`, `sync_status` |
| `asset_history` | 路产变更历史记录 | 主键 `id`，索引 `asset_id`，严格只增不改，杜绝历史状态被冲刷丢失 |
| `photos` | 现场实景照片 | 主键 `id`，存储 Base64/Blob 与 EXIF 经纬度、方位角 |
| `videos` | 行车视频切片元数据 | 主键 `id`，记录切片起止时间、文件大小、上传偏移字节数 |
| `video_events` | 视频证据关联事件 | 主键 `id`，索引 `asset_id`, `video_id`，毫秒级绑定视频帧偏移 |
| `sync_queue` | 优先级待同步队列 | 主键 `id`，索引 `priority`, `status`，驱动 5 级可靠重试传输 |

## 3. 防休眠与持续运行保障 (Screen Wake Lock)

车载巡查时，手机多固定在支架上长时间录制与采集。若系统休眠锁屏，Web 进程与 GPS 定位将被系统挂起：
- 集成 **Screen Wake Lock API** (`navigator.wakeLock.request('screen')`)，在巡查开启时自动申请屏幕常亮唤醒锁。
- 巡查结束或异常退出时自动释放唤醒锁，兼顾行车采集稳定性与车载设备散热降耗。

---

## 4. 数据防覆盖与历史追溯机制 (`AssetHistory`)

在实际巡线中，行车途中仅做一键秒级点位初标，停车休整或审核复核时需补充照片或修正文字。
- 系统**严禁使用覆盖更新冲刷原记录**；
- 每次现场补充说明、状态核实或工单维护，均生成一条不可篡改的 `AssetHistoryRecord`：
  - 记录修改人（`operator_name`）、修改时间（`timestamp`）、新旧属性（`previous_status`, `new_status`）；
  - 关联当时生成的视频证据事件（`video_event_id`），实现路产全生命周期数字档案透明可追溯。

---

## 5. 验证与测试标准

在 `server/tests/offline-sync.test.ts` 中涵盖全套自动化验证：
1. **纯离线环境数据采集与保存**：无网络下采集 GPS 轨迹、5 种路产与切片，全量入库本地队列。
2. **移动端重启数据不丢失**：模拟设备重启刷新，100% 还原未同步状态。
3. **网络恢复 5 级自动同步**：按 P1 至 P5 优先级次序有序上传。
4. **中断再续传**：大文件切片 50% 断网无脏数据，网络恢复后继续上传剩余 50%。
5. **全链路幂等性**：使用客户端 UUID 多次重试，服务端返回 201/200，绝无重复数据。
6. **视频-路产帧联动**：通过路产 ID 秒级定位视频对应切片与帧秒数偏移。
